# Unified Control cooler worker

UC 0.3.0 stand-down (2026-11-02): the installed combined app pins this worker to
`88cd041c4a4a19d66bd332b913ba34d745b075a2`. Consolidating the reviewed worker/health
history onto this repository's main does not change that pin, install a new
standalone CoolerScreen build, or establish physical cooler recovery. The
descriptor-failure incident and deferred cable/sleep checks remain recorded in
`oldbugo/unified-control`'s acceptance and connection-health documents.

This is an engine entry point for the combined app, built with `cargo build --manifest-path src-tauri/Cargo.toml --bin uc-cooler-worker`. It reuses `cs_core` from this repository; it does not launch the CoolerScreen GUI, tray or installed application. UC packages the reviewed executable and the existing ffmpeg/resources separately.

The worker requires `UC_COOLER_WORKER=1` and an absolute `COOLERSCREEN_HOME`. The host supplies only private inherited stdin/stdout handles; there is no named command endpoint or command HTTP server. Lines are JSON, version 1, capped at 32 MiB before parsing. Requests are `{v:1,id:u64,command:string,args:object}`. Responses are `{v:1,id,ok:true,result}` or `{v:1,id,ok:false,error:{error,status,code,...}}`. Events are `{v:1,event,payload}` for `ready`, `cs:job`, `cs:library`, `cs:device` and `cs:app`. The ready payload includes engineVersion, capabilities, fake and blocked/message. No protocol contents are logged.

Every request uses a named allowlisted command and validated arguments. At most 16 requests are admitted; writes are serialized while state/activity remain responsive. Shutdown refuses while an admitted request, visible user job or device upload remains, preserving CoolerScreen's busy contract. Cancellable thumbnail/preview jobs are stopped through the existing App shutdown path. Once accepted it stops admission, ends Live, stops the scheduler, closes ETW and ffmpeg/media resources, and exits. EOF means the parent is gone: admitted operations and noncancellable uploads settle before the same cleanup. The host must not force termination during upload. A response is published only after its request leaves admission.

In native mode a `Local\\UnifiedControlCoolerEngine` mutex prevents a second UC cooler worker in the same Windows session. Existing CoolerScreen detection blocks startup operations and reports `cooler_owned`; mutating commands check again in case CoolerScreen starts later. A blocked worker allows local state/list queries and shutdown. The hardware's existing exclusive handle remains the final ownership check. The native worker has a never-visible top-level session listener that preserves saved sleep/lock/shutdown behavior; it creates no tray or visible window. UC owns the visible tray.

Startup initializes the existing library/gallery/live-theme data but never starts saved Live playback automatically. The host invokes `activate {}` after readiness for an enabled engine to reapply saved Live; it starts Live only when `settings.live.inApp` was already true. This also gives crash recovery an explicit restore operation. New empty homes get an explicit private Gallery path. Fake mode uses FakeMedia, NoSources and a null Live sink; it never opens USB, uses ffmpeg or starts sources. The existing tokenized loopback media server serves previews/Range video and twin frames; mediaBase is returned through App state. The random token is private runtime state and must not be logged/exported.

The dispatcher covers existing themes, imports, versions/Embedded, loop selection, source browsing, preview/digital twin, screen fit, weather, widget status and Live methods. `import_bytes` takes `{name,bytes:[u8]}` or `{name,base64:string}`; `theme_asset_add` adds `originalId` to that payload, or accepts its existing path form. Larger files require the existing `import_path` method or a future chunked upload. Global Windows startup is owned by UC: `live_set.patch.autostart` is rejected rather than changing CoolerScreen's registry entry. Native `original_reveal` and `gallery_open` use the existing App methods. Native setup/restore/reconnect use the existing device queue and reviewed bundled scripts; a missing script reports a resources error before queuing. All five operations reject simulated mode to prevent desktop/privilege side effects in tests. They were not executed during automated verification.

Migration belongs to UC, before worker enable. Copy the existing settings, companion config and library into a new worker home with a preserved original fallback. Copy the gallery rather than sharing it: rename/delete commands modify original files. Rebase settings.galleryDir, original.json file paths and version overlay/effect file paths under copied prefixes. Relative theme assets stay relative. Existing source folders are external references, not files to copy recursively. Existing user data must never be used by automated tests.

Release checks still required: native ownership/enable/disable with the user present; unchanged Live/Embedded behavior; real ffmpeg resources; full UI bridge and large import behavior; migration dry run on a copy; host busy/Quit and crash isolation; privilege script routing; physical sleep/resume when the user elects to test it. Pure/fake worker tests and inherited-pipe integration are software evidence only.

## Connection health and explicit recovery (2026-11-01)

`health_status` is read-only and stays responsive during mutating requests. It returns whitelisted Live connection/hold state, retry counts, coarse connect/stream stage and RX/status counters; raw messages, paths and identifiers are excluded. It opens no USB handle. UC owns periodic background sampling and bounded local logs. Coarse stage is not proof of the exact failed firmware command or visible pixels.

Manual `device_reconnect` now distinguishes missing enumeration from a normally enumerated but unresponsive cooler. The latter invokes the reviewed script with explicit `-ResetPresent`, requires exactly one physical cooler parent/location and hub interface, asks Windows elevation, resets once and verifies a real firmware answer afterward. Fake mode refuses native effects. Normal script invocation without that flag retains its old present-device no-op and exact failed-history recovery. Automatic health sampling never calls recovery/elevation. A successful port-cycle request or normal PnP node alone is not recovery proof.

## Live step diagnostics (engine4.21.1)

After connect/stop transactions the worker can emit private `cs:connection_trace` records: schema1, sequence, finite operation/step/result codes and bounded elapsed milliseconds. No USB reply payload, device identity or arbitrary error text crosses this path. A16-entry nonblocking queue prevents pipe pressure from holding the sender; shutdown permits250ms to drain and may drop remaining records. UC validates again, handles the event internally and writes to its existing rotated health log only while diagnostics are enabled and migration is complete. No public action/RPC or physical probe is added. A successful write is a transport result, not confirmed Embedded playback or pixels.

The250ms limit applies to the diagnostic drain, not all shutdown IPC: existing stdout protocol writes can still wait on a stalled parent. A close/ok step means the existing close routine returned; its ignored native release errors are not independent USB-release verification.

Software verification2026-11-06: eight session/trace tests and ten private worker/source cases pass. The fake sequence adapter covers each handshake failure, existing cancellation checkpoints, exact write/wait ordering, all stop variants continuing after failures and finite redacted records. Worker queue saturation proves Live enqueue stays nonblocking and the diagnostic drain is bounded. Physical recovery is not established.

## Crash handling (engine 4.22.0)

Release builds unwind on panic (`panic = "unwind"`); `src-tauri/src/core/sync.rs` is a port of Unified Control's crash helpers. Locks use poison-tolerant helpers (`lock_or_recover`, `read_or_recover`, `write_or_recover`, `try_lock_or_recover`); the library's version index uses `lock_or_reset` and is read again from disk after a crash. A crashing worker request returns "Cooler request failed." and a crashing scheduler job fails with "Internal error (the task crashed)." without ending the worker. The trace sender drops only the crashing trace. The live data samplers and the source worker's music loop start again after a crash (1 s, doubling to 30 s). The worker installs the panic hook with role `cooler-worker` (`cooler-sources-worker` in source mode) and exits with code 101 on any unguarded panic, so UC restarts a clean worker. Each panic or lock recovery writes at most one line to that process's device.log (32 per run, 160 characters, user folders replaced by placeholders). USB command order and timings are unchanged.
